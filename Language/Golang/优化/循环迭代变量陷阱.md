## 循环迭代变量陷阱

Go 的循环变量在闭包、goroutine、指针引用中容易被误用。Go 1.22 起，`for range` 循环变量的语义已经调整为每次迭代创建新的变量，但旧版本代码、传统 `for` 循环和兼容性场景仍然需要明确理解这个问题。

## 典型问题

在 Go 1.22 之前，下面代码中的闭包捕获的是同一个 `v` 变量，goroutine 实际执行时可能都看到最后一次迭代的值。

```go
for _, v := range values {
    go func() {
        fmt.Println(v)
    }()
}
```

旧版本或需要兼容旧语义时，应在循环体内重新绑定变量，或者通过参数传入闭包。

```go
for _, v := range values {
    v := v
    go func() {
        fmt.Println(v)
    }()
}

for _, v := range values {
    go func(v string) {
        fmt.Println(v)
    }(v)
}
```

## 指针陷阱

对循环变量取地址也容易出错。旧语义下，`&v` 指向的是同一个循环变量地址，而不是切片中每个元素的地址。

```go
var ptrs []*int
for _, v := range values {
    ptrs = append(ptrs, &v) // 旧版本中容易全部指向同一个变量
}
```

需要保存元素地址时，优先使用索引。

```go
for i := range values {
    ptrs = append(ptrs, &values[i])
}
```

## Go 1.22 后的变化

Go 1.22 对 `for range` 引入了按迭代创建变量的新语义，常见闭包捕获问题大幅减少。但仍建议：

- 阅读老代码时确认模块的 Go 版本和编译语义。
- 对传统三段式 `for` 循环保持警惕。
- 涉及 goroutine、闭包、指针保存时显式传参更清晰。

## 实践建议

- 在循环中启动 goroutine 时，优先把循环值作为参数传入函数。
- 不要对 range 变量取地址来代表原集合元素。
- Code Review 时重点检查 `go func()`、`defer func()`、`append(&v)` 这类写法。
