## Redis 缓存雪崩（击穿）、穿透

### 缓存穿透

描述：

缓存和数据源中都没有的数据；请求从缓存获取不到，请求都会到数据源，导致数据源崩溃

解决方案：

1. 接口层增加校验
2. [[../../../Algorithm/奇门遁甲/布隆过滤器（Bloom Filter）]]，适合缓存关键字重复率低且搜索关键字多的场景
3. 空值也缓存，但缓存的有效时间较短，如30秒，适合缓存关键字具有较高重复率场景

### 缓存雪崩（缓存击穿）

描述：

缓存中没有数据，数据源中有数据；请求从缓存获取不到，请求都会到数据源，导致数据源崩溃

缓存雪崩：缓存服务器关闭或者大量缓存集中失效，压垮数据源

缓存击穿：热点数据过期

解决方案：

1. 随机缓存缓存过期时间
2. 分布式部署(redis Cluster 或者 redis Sentinel)，热点数据分布均匀
3. 限流hystrix
4. 使用互斥锁
5. 设置热点数据永远不过期或者异步更新缓存数据

### 热点数据

解决方案：

1. 拆分复杂结构
2. 迁移热点（Redis Cluster）
3. 多副本，复制多份缓存副本，将请求分散到多个节点上，减轻单台缓存服务器压力，适合多读少写
