## HTTP Header 命名规范

HTTP 请求头参数中含有**下划线 `_`** 时，在某些代理/网关（如 Nginx）中会被**静默丢弃**。

### 原因

- HTTP 规范（RFC 7230）建议 Header 名称使用**中划线 `-`** 而非下划线。
- Nginx 默认配置 `underscores_in_headers off`，会忽略包含下划线的 Header。
- 许多代理、CDN、负载均衡器遵循同样的规则。

### 解决方案

1. **应用侧**：自定义 Header 统一使用 `X-Custom-Header` 格式（中划线）。
2. **Nginx 配置**：`underscores_in_headers on;`（不推荐，应优先规范命名）
3. **反向替代**：在网关层将中划线转换为应用期望的下划线格式。

### 命名风格对比

| 风格 | 示例 | HTTP 兼容 |
|------|------|-----------|
| 中划线（推荐） | `X-Request-Id` | 完全兼容 |
| 下划线 | `X_Request_Id` | 部分网关丢失 |
| 驼峰 | `XRequestId` | HTTP Header 不区分大小写 |
