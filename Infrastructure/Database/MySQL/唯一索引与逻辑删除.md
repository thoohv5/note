## 概述

### **唯一索引（Unique Index）**

唯一索引是数据库约束，确保某列或列组合的值在表中是唯一的。

### **特征**

1. **数据完整性**：防止重复值出现
2. **查询优化**：加速唯一值查找
3. **自动校验**：数据库自动强制执行
4. **多列组合**：可跨多列建立组合唯一约束

### 逻辑删除（**Logical Deletion / Soft Delete**）

逻辑删除是一种数据删除策略，它不会真正从数据库中移除记录，而是通过标记字段来标识记录已被"删除"。

### **特征**

1. **标记而非移除**：使用**`is_deleted`**、**`status`**、**`deleted_at`**等字段标记记录状态
2. **数据保留**：被删除的记录仍保留在数据库中
3. **可恢复性**：通过修改标记状态可轻松恢复数据

## 问题

逻辑删除记录被标记为删除但仍保留在数据库中时，可能会导致与唯一索引的约束冲突。

<aside>
💡

在`MySQL`数据库中，当某个字段设置了唯一约束（`Unique Constraint`），如果该字段存在`NULL`，那么唯一约束将失效，即允许多条记录中该字段的值为`NULL`。

</aside>

### 场景

在`gorm`中，我们实现软删除，常常使用以下结构

```go
// go代码
type Order struct {
  // gorm.io/gorm@v1.26.0/model.go
	gorm.Model
	OrderNum string `gorm:"column:order_num;type:varchar(60);not null;default:'';uniqueIndex:udx_orders_order_num;comment:'订单编号'"
}

// sql代码
CREATE TABLE `orders` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  `created_at` datetime(3) DEFAULT NULL,
  `updated_at` datetime(3) DEFAULT NULL,
  `deleted_at` datetime(3) DEFAULT NULL,
  `order_num` varchar(60) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '' COMMENT '''订单编号''',
  PRIMARY KEY (`id`),
  UNIQUE KEY `udx_orders_order_num` (`order_num`),
  KEY `idx_orders_deleted_at` (`deleted_at`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

如果结构中存在字段（如：`order_num`）需要唯一索引，你会发现在删除数据，然后新增数据的时候，会提示你唯一键冲突：`Error 1062 (23000): Duplicate entry '123' for key 'udx_orders_order_num'`。为啥，因为软删除，是标记删除，数据库中已经存在一个删除的`order_num` 的数据，现在新增的一个相同的`order_num`数据当然冲突。

既然问题找到了，那简单呀，我就把唯一索引改成`goods_num`和`deleted_at`，

```go
// go代码
type Order struct {
	// gorm.io/gorm@v1.26.0/model.go
	gorm.Model
	OrderNum  string         `gorm:"column:order_num;type:varchar(60);not null;default:'';uniqueIndex:udx_orders_order_num;comment:'订单编号'"`
	DeletedAt gorm.DeletedAt `gorm:"uniqueIndex:udx_orders_order_num;"`
}

// sql 代码
CREATE TABLE `orders` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  `created_at` datetime(3) DEFAULT NULL,
  `updated_at` datetime(3) DEFAULT NULL,
  `deleted_at` datetime(3) DEFAULT NULL,
  `order_num` varchar(60) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '' COMMENT '''订单编号''',
  PRIMARY KEY (`id`),
  UNIQUE KEY `udx_orders_order_num` (`order_num`,`deleted_at`),
  KEY `idx_orders_deleted_at` (`deleted_at`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci 
```

但是你会发现唯一索引失效了。

## 解决办法

### **调整新增逻辑实现**

新增时分情况处理，如果数据不存在，直接插入新数据；如果数据存在（但是被标记了删除），删除标记并更新数据。

**示例：**

```go
// go代码
type Order struct {
  // gorm.io/gorm@v1.26.0/model.go
	gorm.Model
	OrderNum string `gorm:"column:order_num;type:varchar(60);not null;default:'';uniqueIndex:udx_orders_order_num;comment:'订单编号'"
}

// Upsert方案：依靠唯一索引，创建数据，冲突就更新
db.Clauses(clause.OnConflict{
	Columns:   []clause.Column{{Name: "order_num"}},
	UpdateAll: true,
}).Create(&Order{
	OrderNum: "123",
})

// Assign+FirstOrCreate方案：依赖查询，先查询，存在更新；不存在新增
// 未找到，根据条件和 Assign 属性创建记录
// 找到了，根据 Assign 更新记录
db.Where(&Order{OrderNum: "123"}).Assign(&Order{"其他字段": "其他值"}).FirstOrCreate(&Order{})
```

Upsert方案：性能更好；Assign+FirstOrCreate方案：更加灵活，不依赖数据库；

### **调整删除字段类型实现**

既然是 `deleted_at` 为`NULL`时，出现的问题，`MySQL`中`NULL`与`NULL`不相同，我就改变`deleted_at`的类型，不存储时间格式或`NULL`，改成存储时间戳或0。

**示例：**

```go
// go代码
type Order struct {
	OrderNum  string                `gorm:"column:order_num;type:varchar(60);not null;default:'';uniqueIndex:udx_orders_order_num;comment:'订单编号'"`
	DeletedAt soft_delete.DeletedAt `gorm:"uniqueIndex:udx_orders_order_num"`
	gorm.Model // 放在DeletedAt之后
}

// sql代码
CREATE TABLE `orders` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  `created_at` datetime(3) DEFAULT NULL,
  `updated_at` datetime(3) DEFAULT NULL,
  `order_num` varchar(60) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '' COMMENT '''订单编号''',
  `deleted_at` bigint(20) unsigned DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `udx_orders_order_num` (`order_num`,`deleted_at`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
```

需要修改数据库字段类型和代码，但需要考虑存量数据的问题，还是比较麻烦。需要提前设计。

<aside>
💡

为 DeletedAt 字段创建唯一组合索引时，您必须在插件 `gorm.io/plugin/soft_delete` 的帮助下使用其他数据格式，如 unix second/flag

**注意`gorm.Model`和`DeletedAt`字段的顺序**

</aside>

### **虚拟列的条件索引实现**

通过在表中添加一个虚拟列（生成列），然后在这个列上创建索引解决逻辑删除和唯一索引冲突时，可以通过条件索引仅索引未被逻辑删除的记录来避免冲突。

**示例：**

```bash
*-- VIRTUAL语法仅适用于 MySQL*
**ALTER** **TABLE** orders **ADD** **COLUMN** vt_order_num VARCHAR(60) **GENERATED ALWAYS** **AS** (**case** **when** (deleted_at IS NULL) **then** order_num **end**) VIRTUAL;

**CREATE** **UNIQUE** **INDEX** udx_orders_order_num **ON** orders(vt_order_num);

--- sql代码
CREATE TABLE `orders` (
  `order_num` varchar(60) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT '' COMMENT '''订单编号''',
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  `created_at` datetime(3) DEFAULT NULL,
  `updated_at` datetime(3) DEFAULT NULL,
  `deleted_at` datetime(3) DEFAULT NULL,
  `vt_order_num` varchar(60) COLLATE utf8mb4_unicode_ci GENERATED ALWAYS AS ((case when isnull(`deleted_at`) then `order_num` end)) VIRTUAL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `udx_orders_order_num` (`vt_order_num`),
  KEY `idx_orders_deleted_at` (`deleted_at`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci 
```

### **唯一索引条件索引实现**

通过条件索引仅索引未被逻辑删除的记录来避免冲突。

```sql
*-- MySQL8.0+*
CREATE UNIQUE INDEX `udx_orders_order_num` ON `orders` ((IF(`deleted_at` IS NULL, order_num, NULL)));

--- sql代码
CREATE TABLE `orders` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `created_at` datetime(3) DEFAULT NULL,
  `updated_at` datetime(3) DEFAULT NULL,
  `deleted_at` datetime(3) DEFAULT NULL,
  `order_num` varchar(60) NOT NULL DEFAULT '' COMMENT '''订单编号''',
  PRIMARY KEY (`id`),
  UNIQUE KEY `udx_orders_order_num` ((if((`deleted_at` is null),`order_num`,NULL))),
  KEY `idx_orders_deleted_at` (`deleted_at`)
) ENGINE=InnoDB AUTO_INCREMENT=3 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci
```

### 数据表触发器检查实现

通过**使用CHECK约束+触发器**来避免冲突。

```bash
-- 添加CHECK约束（MySQL 8.0.16+支持）
ALTER TABLE `orders` 
ADD CONSTRAINT `chk_order_num_unique` 
CHECK (
    NOT EXISTS (
        SELECT 1 FROM `orders` o2 
        WHERE o2.order_num = orders.order_num 
        AND o2.deleted_at IS NULL 
        AND o2.id != orders.id
    ) OR orders.deleted_at IS NOT NULL
);

-- 添加触发器确保实时检查
DELIMITER //
CREATE TRIGGER trg_order_num_unique
BEFORE INSERT ON orders
FOR EACH ROW
BEGIN
    IF NEW.deleted_at IS NULL AND EXISTS (
        SELECT 1 FROM orders 
        WHERE order_num = NEW.order_num 
        AND deleted_at IS NULL
    ) THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Duplicate order_num for active order';
    END IF;
END//
DELIMITER ;
```
