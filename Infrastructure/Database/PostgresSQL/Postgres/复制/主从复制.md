## 主从复制

## 主库

```jsx
## 配置 postgres.conf

## minimal: WAL级别最小配置，replica: 流复制和流事务，logical：逻辑复制
wal_level = replica
## 复制进程
max_wal_senders = 10
## 流复制超时时间
wal_sender_timeout = 60s
## 归档/数据查询
hot_standby = on

## 创建复制角色
CREATE ROLE replication LOGIN PASSWORD 'password' REPLICATION;

## 访问权限 pg_hba.conf
host    replication     0      192.168.247.0/24        md5

----------------------单库复制-----------------------

## 逻辑复制
wal_level = logical
## 复制插槽数量
max_replication_slots = 1

## 创建逻辑复制角色
SELECT pg_create_logical_replication_slot('slot_name', 'database_name');

```

```sql
su - postgres -c 'pg_ctl restart -D /data/postgres/data/'

su - postgres -c 'pg_ctl reload -D /data/postgres/data/'

```

## 从库

```jsx
## 配置 postgresql.conf
## 最长上报状态时间
wal_receiver_status_interval = 10s
## 复制异常上报
hot_standby_feedback = on

## 配置 postgres.auto.conf
standby_mode = 'on'
primary_conninfo = 'host=primary_host port=primary_port user=replication password=password'
primary_slot_name = 'slot_name'

```

```sql
su - postgres -c 'pg_ctl stop -D /data/postgres/data/'
cd /data/postgres/data
rm -rf *

## 将主库数据拷贝至从库, -R
pg_basebackup -h 10.2.19.162 -p 5432 -D /data/postgres/data/ -F p -X stream -v -P -U replication -R

pg_basebackup -h 10.2.19.203 -p 5435 -D /usr/local/appdata/normal/data/cloudzddi -F p -X stream -v -P -U replication -R

chown -R postgres:postgres .

```

```sql
## 提升主库
pg_ctl promote

```

PostgresSQL 12 开始使用`standby.signal` 替换 `recovery.conf` 该文件只是一个标识文件，它的存在就是告诉数据库，当我们执行`pg_ctl start`启动的时候，当前库的角色是standby，不是primary角色

## 验证

```sql
## 备库是t,主库是f
select pg_is_in_recovery();

## 主库
select * from pg_stat_replication;

## in production/in archive recovery
pg_controldata | grep cluster

ps -ef | grep wal
wal 日志发送进程"wal sender process"，说明是主库。
wal 日志接收进程"wal receiver process" ，说明是备库；

```
