# B+树数据量的计算

InnoDB存储引擎的最小存储单元页（Page） 16K

```lua
show variables like 'innodb_page_size'
```

叶子节点：存放行数据

假设一行记录的数据大小为1K，单个叶子节点（页）中的记录数=16K/1K = 16

非叶子节点：存放键值和指向数据页的指针

假设主键ID为bigint类型，长度为8字节，而指针大小在InnoDB源码中设置为6字节，总计14字节，单个叶子节点（页）中的键数据=16K/14=1170

一颗高度为3的B+树，能够存放1170*1170*16=21902400条数据记录

## 为什么MySQL的索引要使用B+树而不是其他树形结构？比如B树？

因为B树不管叶子节点还是非叶子节点，都会保存数据，这张导致在非叶子节点中能保存的指针数据量变少（有些资料也称为扇出），指针少的情况下要保存大量数据，只能增加树的高度，导致IO操作变多，查询性能变低
