# 连接数问题

### 问题

```bash
recv() failed (104: Connection reset)
connect() to upstream failed (111: Connection refused)
worker_connections are not enough
too many open files
```

### 核心参数

```bash
# 工作进程数（一般等于 CPU 核心数）
worker_processes auto;

**#** 每个 worker 允许的最大连接数
****worker_connections 1024;
```

### 理论连接数

```bash
max_connections = worker_processes × worker_connections

假设机器 4 核：
max = 4 × 1024 = 4096
如果是反向代理 → 有效最大 QPS 约 2000 多
```

<aside>
💡

一个客户端可能占用 1 个连接，但作为反向代理时会占用 2 个连接（client + upstream）

</aside>

## 推荐配置

```bash
worker_processes auto;

events {
	  # Linux 通常允许单 worker 上限约 65535
    worker_connections 65535;
    # epoll 提高并发
    multi_accept on;
    # multi_accept 一次接多个连接
    use epoll;
}
```

### 查看Nginx当前连接数

- 1. nginx_status
    
    ```bash
    # 部署
    location /nginx_status {
        stub_status;
        allow 127.0.0.1;    # 允许本机
        deny all;
    }
    
    # 加载
    nginx -s reload
    
    # 请求
    curl http://127.0.0.1/nginx_status
    ```
    
- 2. 系统层面查看 Nginx 进程 TCP 连接
    
    ### **全部连接数**：
    
    ```
    ss -ant | grep -E 'nginx|:80|:443' | wc -l
    
    ```
    
    ### 查看 ESTABLISHED（真实活动连接）：
    
    ```
    ss -ant | grep ESTAB | grep -E 'nginx|:80|:443' | wc -l
    
    ```
    
    ### 查看连接状态统计：
    
    ```
    ss -s
    ```
    

### 问题

- 1. **系统连接（FD）限制不够**
    
    ```bash
    41626: no space left on device
    too many open files
    ```
    
    解决
    
    ```bash
    # limit 限制
    vim /etc/security/limits.conf
    * soft nofile 100000
    * hard nofile 100000
    
    # sysctl 调优
    sudo sysctl -w net.core.somaxconn=65535
    sudo sysctl -w net.ipv4.ip_local_port_range="1024 65535"
    sudo sysctl -w net.ipv4.tcp_max_syn_backlog=65535
    sudo sysctl -w net.core.netdev_max_backlog=65535
    ```
