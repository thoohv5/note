## Redis 开发使用规范

[TOC]

### 1. 前言

为形保障公司项目代码的易维护性和数据库安全性，特制定本规范。每项规范内容，给出了要求等级，其定义为：

- **必须（Mandatory）**：用户必须采用；
- **推荐（Preferable）**：用户理应采用，但如有特殊情况，可以不采用；
- **可选（Optional）**：用户可参考，自行决定是否采用；

### 2. 数据库链接

### 2.1【推荐】使用短链接,使用后自动释放连接
```go
cli := redis.NewClient(&redis.Options{
	Addr:     "10.2.18.51:4580",
	Password: "*****",
})
cli.Do("xxxx")
defer cli.Close()
```
### 2.2【必须】使用长链接时，每次执行命令前必须ping检测链接是否有效
```go
var cli =  redis.NewClient(&redis.Options{
	Addr:     "10.2.18.51:4580",
	Password: "*****",
})

_,err := cli.Ping().Result()
if err != nil {
	// todo 重连
}
```
### 2.3【推荐】高并发下建议客户端添加熔断功能



### 3. Key和value设计

### 3.1【推荐】缓存 Key 设置失效时间

 建议使用expire设置过期时间(条件允许可以打散过期时间，防止集中过期造成缓存雪崩) 

```
cli.Set("k1","v1",time.Second * 10) // 设置10秒过期
```
### 3.2. redis key命名规范

 可读性高的Key命名有助于排查线上问题、方便的进行批量处理 ，当前redis内存暴涨，通过高频key前缀可以轻易的区分出是哪个系统的哪个模块在频繁操作，快速定位问题。当定位到线上问题时，可以通过模式匹配批量处理该类Key 

- 【必须】Redis key命名需具有可读性以及可管理性，不该使⽤含义不清的key以及特别长的key名

- 【必须】以英⽂字母开头，命名中只能出现小写字母、数字、英⽂点号(.)和英文半角冒号(:)

- 【必须】不要包含特殊字符，如下划线、空格、换行、单双引号以及其他转义字符

- 【推荐】命名模板：{业务模块名}:{业务逻辑含义}:{其他}:{value类型}

- 【推荐】同⼀业务逻辑含义段的单词之间使⽤英⽂半⾓点号 (.)分割，用来表⽰⼀个完整的语义
### 3.3.【推荐】 选择适合的数据类型

- Strings类型: 单个kv存储、适用于如简单计数等。

- Hash类型: 多个相关属性放到一个Hash中、适用于如存储对象。

- Set类型: 集合类型、适用于如归类对象等

- Sorted Set类型: 有序集合类型、适用于如榜单排行

- Lists类型: 队列类型、适用于如队列、粉丝/关注列表等

反例:

```
set user:1:name tomset user:1:age 19set user:1:favor football
```

正例:
```
hmset user:1 name tom age 19 favor football
```

### 3.4【必须】慎用大key

大key数据存入Redis，除了带来极大的内存占⽤外，在并发高时，很容易就会将⽹卡流量占满，进而造成整个服务器上的所有服务不可用。

- string类型控制在10KB以内，hash、list、set、zset元素个数不要超过5000。
- 非字符串的bigkey，不要使用del删除，使用hscan、sscan、zscan方式渐进式删除
-   注意bigkey过期时间，过期后会自动触发del造成阻塞，并且该del不会记录到慢查询 


### 4. 规范命令使用

### 4.1.【推荐】cluster模式慎用 mget 操作
Redis Cluster 的 MGET 操作，会到各分片取数据聚合，相比传统的 M/S架构，性能会下降很多，请提前压测和评估


### 4.2.【必须】禁止使用以下运维命令(建议dba通过rename机制禁止这些命令)

- config set :  运维人员才可以进行数据库设置
- flushall,flushdb:  禁止删库
- keys * :  Keys 命令效率极低，属于 O(N)操作，会阻塞其他正常命令，在 cluster 上，会是灾难性的操作
- shutdown:  只有运维人员可以关机
- monitor :  只有运维人员可以使用
- save,bgsave,bgrewriteaof :  禁止手动刷新rdb 和aof文件

### 4.3.【推荐】使用批量操作提高效率

- 原生命令 ：使用 mget、mset 代替
- 非原生命令:  使用 pipeline 减少网络io
- Pipeline建议一次执行的命令数不超过30 条

注意：1. 原生是原子操作，pipeline是非原子操作。 2. pipeline可以打包不同的命令，原生做不到

### 4.4.【推荐】关注时间复杂度O(N)的命令
禁止对set、zset 、list的不设范围操作。有遍历的需求可以使用hscan、sscan、zscan代替并在客户端进行去重

### 5. 其他注意项目

### 5.1.【可选】Redis事务

 Redis的事务功能较弱(不支持回滚)，而且集群版本(自研和官方)要求一次事务操作的key必须在一个slot上(可以使用hashtag功能解决) 

### 5.2.【可选】不使用多个db
默认使用db0，如果需要切分业务线，在配置⽂件中定义各业务线使用的前缀 通过key来区分业务类型

### 5.3.【可选】慎用消息队列

Redis List常被用作消息队列服务。因为功能相对简单，不支持消息重传、持久化等功能，当消费者崩溃时可能导致数据丢失。因此对于要求消息可靠性高的场景，建议使用更加专业的MQ软件

### 5.4.【可选】慎用Eval

lua 脚本虽然能做很多看起来很 cool 的事情，但它就像是 SQL 的存储过程，会引入性能和一些难以维护的问题
