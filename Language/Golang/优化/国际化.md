## 国际化

国际化通常缩写为 i18n，目标是让程序可以根据语言、地区、时区、货币、数字格式等本地化规则展示内容。Go 项目中常见需求包括错误消息翻译、模板文案翻译、时间和金额格式化。

## 核心关注点

- 文案不要硬编码在业务逻辑中，应抽离为消息 ID 或翻译资源。
- 语言选择通常来自用户设置、`Accept-Language` 请求头或租户配置。
- 翻译资源需要支持占位符，例如用户名、数量、金额等变量。
- 时间、日期、数字、货币等格式不只是翻译文本，还要符合地区习惯。

## Go 实现方式

常见方案是使用 `golang.org/x/text` 生态或第三方 i18n 库：

```go
// 伪代码：根据语言标签选择消息模板
lang := "zh-CN"
messageID := "user.created"
text := localizer.Localize(lang, messageID, map[string]any{
    "Name": "Tom",
})
```

项目落地时建议把翻译文件放到独立目录，例如：

```text
locales/
  zh-CN.toml
  en-US.toml
```

## 实践建议

- 后端返回稳定错误码，前端或网关负责最终文案本地化。
- 如果后端直接返回文案，要同时记录语言来源，便于排查问题。
- 翻译文件要纳入版本管理，避免线上热更新造成文案与代码不一致。
- 对复数、性别、单位换算等规则复杂的语言，优先使用成熟 i18n 库。
