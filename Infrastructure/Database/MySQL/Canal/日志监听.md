## MySQL binlog 监听工具

### 主流工具对比

| 工具 | 开发方 | 特点 |
|------|--------|------|
| **Canal** | Alibaba | Java 实现，纯增量同步，生态丰富（ES/Redis/Kafka） |
| Maxwell | Zendesk | JSON 输出，轻量简单，Go+Kafka 友好 |
| Databus | LinkedIn | 复杂，适合大规模分布式，LinkedIn 内部使用 |
| DTS | 阿里云 | 云服务，全量+增量，无需自建 Canal 集群 |

### Canal 工作原理

1. Canal 伪装成 MySQL Slave，向 Master 发送 dump 协议
2. Master 推送 binary log 事件
3. Canal 解析 binlog，转为结构化数据
4. 通过 Kafka/RocketMQ 等投递到下游消费

### 适用场景

- 数据库变更同步到 Elasticsearch / Redis
- 数据归档 / CDC（Change Data Capture）
- 跨库数据实时一致性

### 注意事项

- 需要 MySQL 开启 binlog，格式为 ROW
- Canal 作为 Slave 需要唯一 server-id
- 注意 binlog 积压和消费位点管理
