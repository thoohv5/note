# 重试队列 & 死信队列

在 RocketMQ 中，**重试队列（`%RETRY%ConsumerGroup`）** 和 **死信队列（`%DLQ%ConsumerGroup`）** 的消息确实有时间限制和生命周期管理机制。以下是详细说明：

---

### **1. 重试队列（`%RETRY%ConsumerGroup`）**

### **消息时间限制**

- **延迟重试时间**：
    
    消费失败的消息进入重试队列后，**不会立即被重新投递**，而是根据重试次数逐步增加延迟时间。RocketMQ 默认的重试时间阶梯如下：
    
    ```
    第1次重试：10 秒
    第2次重试：30 秒
    第3次重试：1 分钟
    第4次重试：2 分钟
    第5次重试：3 分钟
    第6次重试：4 分钟
    第7次重试：5 分钟
    第8次重试：6 分钟
    第9次重试：7 分钟
    第10次重试：8 分钟
    第11次重试：9 分钟
    第12次重试：10 分钟
    第13次重试：20 分钟
    第14次重试：30 分钟
    第15次重试：1 小时
    第16次重试：2 小时（之后固定为 2 小时）
    ```
    
    - 可通过 **`messageDelayLevel`** 参数在 Broker 配置中修改（**`broker.conf`**）。
- **消息存活时间**：
    
    重试队列中的消息**不会自动过期**，只有以下情况会被清除：
    
    1. 被消费者成功消费。
    2. 达到 **`maxReconsumeTimes`** 后被转移到死信队列。
    3. Broker 磁盘空间不足时触发清理（按存储时间淘汰）。

### **配置参数**

**properties**

```toml
# Broker 端配置（broker.conf）maxReconsumeTimes=16  # 最大重试次数（默认16次）
messageDelayLevel=1s 5s 10s 30s 1m 2m 3m 4m 5m 6m 7m 8m 9m 10m 20m 30m 1h 2h  # 自定义延迟级别
```

---

### **2. 死信队列（`%DLQ%ConsumerGroup`）**

### **消息时间限制**

- **消息存活时间**：
    
    死信队列中的消息**默认永久保存**，除非：
    
    1. 手动删除（通过控制台或命令行工具）。
    2. Broker 磁盘空间不足时触发清理（按存储时间淘汰）。
    3. 配置了 **`fileReservedTime`**（默认 72 小时，但通常对死信队列不生效）。
- **无自动消费**：
    
    死信队列的消息需要**人工干预处理**（如手动查询、重新投递或记录日志）。
    

### **配置参数**

**properties**

```
# Broker 端配置（broker.conf）
enableDLQ=true  # 默认开启，无需显式配置
```

---

### **3. 如何查看和管理队列中的消息**

### **查看重试队列消息**

```bash
# 进入 Broker 容器
docker exec -it <broker-container> bash

# 查看重试队列状态
mqadmin queryMsgByTopic -n localhost:9876 -t %RETRY%test_group
```

### **查看死信队列消息**

```bash
mqadmin queryMsgByTopic -n localhost:9876 -t %DLQ%test_group
```

### **手动重新投递死信消息**

```bash
mqadmin sendMsg -n localhost:9876 \
  -t original_topic_name \
  -k "dead_msg_key" \
  -p "resend_body_content"
```

---

### **4. 关键注意事项**

1. **重试队列的延迟时间**是固定的，不可为单条消息自定义（需修改 Broker 配置）。
2. **死信队列无自动重试**，必须人工处理。
3. **生产环境建议**：
    - 监控死信队列，避免堆积。
    - 合理设置 **`maxReconsumeTimes`**（通常 3~16 次）。
    - 对死信队列设置单独的存储策略（如定期归档）。

---

### **总结**

| **队列类型** | **消息存活时间** | **触发清理条件** | **管理方式** |
| --- | --- | --- | --- |
| **重试队列** | 无自动过期 | 成功消费/达到最大重试次数/磁盘清理 | 自动重试 |
| **死信队列** | 默认永久保存 | 手动删除/磁盘清理 | 人工处理 |

通过合理配置和监控，可以确保消息在失败时既不会丢失，也不会无限占用资源。
