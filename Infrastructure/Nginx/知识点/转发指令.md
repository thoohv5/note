# 转发指令

# return指令

- return 指令放在 server 或 location 上下文中。语法很简单

## 作用

1. 重写URL适用于每个匹配的server或location的请求
2. 可以使用标准的Nginx变量构建重写URL

备注：尽量使用return，而不是rewrite

## 语法

```
return code [text];
return code URL;
return URL;

```

## 实例

```
# 下面代码中，listen 指令表明 server 块同时用于 HTTP流量。
# server_name 指令匹配包含域名 ‘www.old-name.com’ 的请求。return 指令告诉 Nginx 停止处理请求，直接返回 301 (Moved Permanently) 代码和指定的重写过的 URL 到客户端。
# $scheme 是协议（HTTP 或 HTTPS），$request_uri 是包含参数的完整的 URI。
server{
    listen         80;
    server_name www.old-name.com;

    # return 指令的第一个参数是响应码。第二个参数可选，可以是重定向的 URL
    # location 和 server 上下文中都可以使用 return 指令。
    return 301 $scheme://www.new-name.com$request_uri;
}

```

# rewrite

## 作用

rewrite规则会改变部分或整个用户请求中的URL

1. 通知客户端，请求的资源发生变化
2. 控制Nginx中的处理流程

## 语法

```
rewrite regex URL [flag];

```

flag标志位：

- last 停止处理当前的指令集，并开始对匹配更改后的URI新的location进程刷新
- break 停止处理当前的指令集
- redirect 返回包含302的临时重定向，在替换字符串不以"http://","https://“或”$scheme"开头时使用
- permanent 返回包含301的永久重定向

## 实例

```
server {
    listen      80;
    server_name chat.paas.scorpio.uat.newtank.cn;

    # 第一个参数 regex 是正则表达式。
    rewrite ^(.*)$	<https://$host$1>	permanent;
}

```
