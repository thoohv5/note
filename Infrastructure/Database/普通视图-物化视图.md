## 普通视图 & 物化视图

以下是 MySQL 中普通视图和物化视图（通过模拟实现）的详细对比：

| 特性 | 普通视图（View） | 物化视图（模拟实现） |
| --- | --- | --- |
| 是否 MySQL 原生支持 | ✅ 是 | ❌ MySQL 不原生支持 |
| 是否存储数据 | ❌ 不存，只是 SQL 封装 | ✅ 存在一张真实的物化表 |
| 查询速度 | 一般（依赖原表实时查询） | 快（直接查已有数据） |
| 实时性 | 实时 | 非实时（需手动或定时刷新） |
| 写入原表是否有影响 | ❌ 没有 | ❌ 没有（但数据不同步会导致查询旧数据） |
| 适合场景 | 查询少、逻辑清晰 | 查询多、性能要求高、可接受延迟 |
| 示例 | CREATE VIEW xxx AS SELECT ... | 用脚本或触发器维护一个 search_index 表 |

在 MySQL 中模拟物化视图的推荐方式：

1. 创建一个物化的中间表（例如 search_index）

2. 写定时任务或脚本同步 users 和 products 表的数据到 search_index

3. 使用 search_index 做分页查询、模糊搜索，加快性能
