## 软件许可证

> 软件许可证定义了使用、修改和分发代码的法律条件。选型时需根据开源策略选择匹配的许可证。

### 常见许可证对比

| 许可证 | 传染性 | 商用 | 修改闭源 | 专利 | 使用场景 |
|--------|--------|------|----------|------|----------|
| **MIT** | 无 | 是 | 可 | 否 | 最宽松，适合工具库 |
| **Apache 2.0** | 无 | 是 | 可 | 是 | 适合涉及专利的项目 |
| **BSD** | 无 | 是 | 可 | 否 | 类似 MIT，更详细免责 |
| **LGPL** | 弱（链接） | 是 | 动态链接 | 否 | 库级别限制 |
| **GPL** | 强（衍生） | 是 | 必须开源 | 否 | 所有衍生代码必须 GPL |
| **AGPL** | 网络也传染 | 是 | 网络使用也触发 | 否 | SaaS 场景的 GPL |
| **MPL 2.0** | 弱（文件级） | 是 | 文件级修改 | 是 | Mozilla 项目中常见 |
| **Zlib/libpng** | 无 | 是 | 可 | 否 | zlib / libpng 等 |
| **CC BY 4.0** | 无 | 是 | 可 | N/A | 文档、非代码作品 |
| **Unlicense** | 无 | 是 | 可 | 否 | 放弃版权，进入公共领域 |

### 关键词含义

- **传染性**（Copyleft）：使用本代码的衍生作品是否需要以相同许可开源
- **弱传染**：仅修改本体需开源，库方式调用不受影响（LGPL）/ 仅修改文件需开源（MPL 2.0）
- **强传染**（GPL）：任何包含/链接/衍生均须以 GPL 开源
- **网络传染**（AGPL）：SaaS 提供服务也触发了开源义务

### 选型建议

- **公司内部项目**：MIT / Apache 2.0 最安全
- **基础库 / SDK**：MIT 或 Apache 2.0（有专利时优先 Apache 2.0）
- **不希望被闭源商用**：GPL / AGPL
- **SaaS 保护**：AGPL

### 注意事项

- 混合使用不同许可证的代码时，最终许可取最严格条款
- 公司代码使用 GPL 库前需要法务评估
- Apache 2.0 与 GPLv2 不兼容，但与 GPLv3 兼容
