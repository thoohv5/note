## 日志清空

## **`truncate` 命令**

### **作用**

- 直接修改文件大小，**不改变文件 inode**（文件仍被进程持有）
- 默认将文件截断为 0 字节（也可指定大小）

### **关键特性**

```bash
truncate -s 0 /path/to/file.log
```

| **优点** | **缺点** |
| --- | --- |
| ✅ 立即释放磁盘空间 | ❌ 文件描述符仍存在 |
| ✅ 不影响持有该文件的进程 | ❌ 文件看似"空"但进程可能继续写入 |
| ✅ 无需重启服务 |  |

### **适用场景**

需要立即释放磁盘空间且不能中断服务时（如 Docker 日志文件）

## **`>` 重定向**

### **作用**

- 通过 shell 重定向清空文件内容

```bash
> /path/to/file.log
```

### **实际行为**

1. 先以写模式打开文件（O_WRONLY | O_TRUNC）
2. 截断文件大小为 0

### **与 `truncate` 对比**

| **对比项** | **`>`** | **`truncate`** |
| --- | --- | --- |
| 系统调用 | open()+ftruncate() | truncate() |
| 进程影响 | 可能被某些程序检测到文件变化 | 更底层直接 |
| 权限要求 | 需要写权限 | 需要写权限 |

**注意**：

对于已删除但被进程占用的文件（显示 **`deleted`** 状态），**`>`** **无法操作**，必须通过 **`/proc/<pid>/fd/<num>`** 处理。

## **`rm` 命令**

### **作用**

- **删除文件链接**（实际数据可能未立即清除）
- 如果文件正在被进程使用：
    - 文件占用的磁盘空间不会立即释放
    - 文件标记为 **`deleted`** 但仍存在于目录项中

### **关键现象**

```bash
rm /path/to/file.log
lsof | grep deleted# 仍可见被进程占用的已删除文件
```

| **优点** | **缺点** |
| --- | --- |
| ✅ 彻底删除文件链接 | ❌ 不释放磁盘空间（如果文件被占用） |
| ✅ 简单直接 | ❌ 需要配合进程重启才能完全清理 |

### **适用场景**

确定文件不再需要且可以重启相关进程时。
