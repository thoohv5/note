## 嵌套事务

MySQL 官方明确不支持嵌套事务：当执行 `START TRANSACTION` 时会隐式提交当前事务。但在复杂系统中函数间相互调用很容易无意中形成嵌套，需要应用层解决。

### Doctrine 方案（Savepoint）

通过 `_transactionNestingLevel` 计数器，首次开启时执行 `BEGIN`，嵌套层（level > 1）时创建 savepoint：

```php
public function beginTransaction() {
    ++$this->_transactionNestingLevel;
    if ($this->_transactionNestingLevel == 1) {
        $this->_conn->beginTransaction();
    } else if ($this->_nestTransactionsWithSavepoints) {
        $this->createSavepoint($this->_getNestedTransactionSavePointName());
    }
}
```

- **rollback**：level == 1 直接回滚，否则回滚到对应 savepoint
- **commit**：level == 1 真正提交，否则释放 savepoint；递减 nestingLevel

优点：嵌套事务相互独立，内层回滚不影响外层。

### Laravel 方案（计数器）

仅用一个计数器，只有最外层才执行真正的 `BEGIN/COMMIT/ROLLBACK`：

```php
public function beginTransaction() {
    ++$this->transactions;
    if ($this->transactions == 1) {
        $this->pdo->beginTransaction();
    }
}
```

内层 `rollback` 仅将计数器减一，最终由最外层统一回滚或提交。

优点：实现简单；缺点：内层没有真正的事务隔离，一旦内层出错需要外层的显式回滚。
