# 滚动更新过程

默认情况下，Deployment 使用滚动更新策略：

### ✅ 创建新 Pod

- 按照 `maxSurge`（默认 25%）策略，Deployment 控制器 **先启动新的 Pod**。
- 新 Pod 会被调度到节点并拉取新镜像，然后启动。

### ❌ 删除旧 Pod

- 当新 Pod 状态变为 `Ready` 后，Deployment 控制器开始 **逐步删除旧的 Pod**。
- 删除数量受 `maxUnavailable`（默认 25%）控制。

> 这个过程会持续进行，直到新 Pod 完全替代旧 Pod。
> 

## 控制升级行为参数（Deployment）

在 YAML 中你可以配置以下参数来控制升级细节：

```yaml
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxUnavailable: 1        # 升级过程中最多几个 Pod 不可用
    maxSurge: 1              # 允许多出来的 Pod 数量（超出 replicas）
```

## 具体行为流程下：

### 1. Kubernetes 向 Pod 容器发送 `SIGTERM`

- 这个信号表示“优雅退出”，允许容器进行资源清理、关闭连接等。
- 容器可以通过捕获 `SIGTERM` 来执行自定义逻辑（例如关闭数据库连接、flush 缓存等）。

### 2. 等待“终止宽限期”（Grace Period）

- 默认是 `30 秒`，你可以通过如下方式修改：

### ✅ 临时指定：

```bash
kubectl delete pod mypod --grace-period=10
```

### ✅ Deployment 中设置：

```yaml
spec:
  template:
    spec:
      terminationGracePeriodSeconds: 10
```

### 3. 如果超时未退出，发送 `SIGKILL`

- 如果容器在宽限期内仍未终止，Kubelet 会发送 `SIGKILL`，强制终止容器。
- 此时容器无法再进行任何清理逻辑。

## 扩展

```sql
Pod Delete Triggered
│
├─ LB 开始 Drain (TERMINATION_DRAIN_DURATION_SECONDS)
│
├─ Pod 收到 SIGTERM (terminationGracePeriodSeconds)
│   ├─ preStop Hook 执行
│   └─ 主进程优雅关闭
│
└─ 超过 terminationGracePeriodSeconds → SIGKILL
```
