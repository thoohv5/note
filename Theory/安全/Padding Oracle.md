## Padding Oracle

Padding Oracle 攻击是一种针对 **CBC（Cipher Block Chaining）模式** 加密系统的侧信道攻击，攻击者利用服务器对 **填充（Padding）验证** 的不同响应来逐步解密或加密数据，而无需知道密钥。

---

### **1. 攻击原理**

### **(1) CBC 模式解密流程**

在 AES-CBC 解密过程中：

1. 密文被分成多个块（每块 16 字节）。
2. 每个块先经过 AES 解密，再与前一个密文块（或 IV）进行 XOR，得到明文。
3. **解密后，检查填充是否合法**（如 PKCS#7）：
    - 如果填充合法，返回明文（或继续处理）。
    - 如果填充不合法，返回 **"Padding Error"**（或其他错误信息）。

### **(2) 攻击者如何利用 Padding Oracle**

攻击者可以：

1. **篡改密文**（如修改 IV 或某个密文块）。
2. **观察服务器的响应**：
    - 如果服务器返回 **"Padding Error"**，说明填充不正确。
    - 如果服务器返回其他错误（如解密成功但数据无效），说明填充正确。
3. **通过反复尝试，逐字节推断明文**。

---

### **2. 攻击步骤（示例）**

假设：

- 攻击者有一个密文块 **C₁**，想解密得到明文 **P₁**。
- 前一个密文块是 **C₀**（或 IV）。
- 解密过程：**P₁ = AES⁻¹(C₁) XOR C₀**。

### **步骤 1：篡改 C₀，观察填充错误**

攻击者可以：

1. 修改 **C₀** 的最后一个字节（**C₀[15]**），并发送 **`(C₀', C₁)`** 给服务器。
2. 如果服务器返回 **"Padding Error"**，说明填充不正确（如填充字节不是 **`0x01`**）。
3. 如果服务器不报错，说明填充可能是 **`0x01`**（即最后一个字节解密后是 **`0x01`**）。

### **步骤 2：计算明文字节**

假设服务器接受 **`C₀'[15]`** 的某个值，说明：

复制

下载

```
AES⁻¹(C₁)[15] XOR C₀'[15] = 0x01
```

因此：

复制

下载

```
AES⁻¹(C₁)[15] = 0x01 XOR C₀'[15]
```

而真正的明文：

复制

下载

```
P₁[15] = AES⁻¹(C₁)[15] XOR C₀[15]
       = (0x01 XOR C₀'[15]) XOR C₀[15]
```

这样，攻击者就能计算出 **`P₁[15]`**。

### **步骤 3：扩展到整个块**

重复此过程，逐步调整 **`C₀`** 的每个字节，最终可以解密整个 **`P₁`**。

---

### **3. 实际攻击案例**

- **2014年，POODLE 攻击（CVE-2014-3566）**：
    
    攻击者利用 SSL 3.0 的 Padding Oracle 漏洞解密 HTTPS 会话。
    
- **2021年，某些 API 未正确验证填充**，导致攻击者可以伪造加密数据。

---

### **4. 防御措施**

### **(1) 使用认证加密（Authenticated Encryption）**

- **推荐模式**：**AES-GCM**、**AES-CCM**、**ChaCha20-Poly1305**（它们自带完整性校验，防止篡改）。
- **替代方案**：在 CBC 模式下使用 **HMAC** 校验密文（Encrypt-then-MAC）。

### **(2) 统一错误响应**

- **不泄露填充信息**：无论填充错误还是解密失败，返回相同错误（如 "Decryption Failed"）。
- **恒定时间（Constant-Time）检查**：避免通过响应时间泄露填充是否正确。

### **(3) 避免使用 CBC + 填充**

- 优先选择 **CTR**、**GCM** 等无需填充的模式。

---

### **5. 总结**

| **攻击方式** | **利用目标** | **防御方法** |
| --- | --- | --- |
| **Padding Oracle** | 服务器返回不同的填充错误 | 1. 使用 GCM/CCM2. 统一错误响应3. 恒定时间填充检查 |

Padding Oracle 攻击表明，**加密本身的安全性不仅依赖于算法，还依赖于实现方式**。因此，务必使用现代加密库（如 OpenSSL、Libsodium），避免手动实现 CBC 解密逻辑。
