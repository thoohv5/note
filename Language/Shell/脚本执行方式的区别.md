日常最常用的**3 种脚本执行方式**（以 Shell 脚本为例，Python / 其他脚本同理），核心区别在于：**是否开启新进程、是否影响当前终端环境、执行权限要求**。

---

假设有脚本：`script.sh`

# `./script.sh`（最标准、最推荐）

**用法**

```
chmod +x script.sh  # 必须先加执行权限
./script.sh
```

**特点**
- 开启**新的子进程**执行
- **不影响当前终端的环境变量**（安全）
- 必须有**执行权限 (x)**
- 必须写 `./` 表示当前目录

**适用场景**：正式运行脚本、生产环境、不想污染当前 shell 环境。

---

# `sh script.sh`

**用法**

```
sh test.sh
```

**特点**
- 开启**新的子进程**
- **不需要执行权限**，只要读权限即可
- 明确指定用 sh 解释器运行

**适用场景**：快速测试、不想改权限、不确定脚本是否有 x 权限。

---

# `source script.sh` 或 `. script.sh`（最特殊）

**用法**

```
source script.sh
# 或简写
. script.sh
```

**特点**
- **在当前 shell 进程直接执行**
- **会修改当前终端的环境变量、目录、变量**
- 不需要执行权限
- 脚本退出、报错都会影响当前终端

**适用场景**：加载环境变量、配置文件（如 `source ~/.bashrc`）。

---

# 区别

|执行方式|新进程|影响当前环境|需要执行权限|
|---|---|---|---|
|`./test.sh`|✅ 是|❌ 不影响|✅ 需要|
|`bash test.sh`|✅ 是|❌ 不影响|❌ 不需要|
|`source test.sh`|❌ 否|✅ **会影响**|❌ 不需要|

---

# 示例

脚本 `cd.sh`：

```
cd /tmp
```

执行效果：

- `./cd.sh` → 当前目录**不变**（子进程 cd 不影响父进程）
- `bash cd.sh` → 当前目录**不变**
- `source cd.sh` → 当前目录**立刻变成 /tmp**

---

## 总结

- **平时运行脚本用 `./脚本` 或 `sh 脚本`**（安全、隔离）
- **加载环境变量用 `source 脚本`**（会修改当前终端）
- 前两种是**子进程**，第三种是**当前进程**，这是最本质区别。
