### Package names（命名规范）

1. By convention, packages are given lower case, single-word names; there should be no need for underscores or mixedCaps.
    
    按照惯例，包名都应该使用小写的单词名称；应该不使用下划线或者大小写混合。
    
2. the package name is the base name of its source directory;
    
    包名称是其源目录的名称。（包名与文件夹名称保持一致）
    
3. The importer of a package will use the name to refer to its contents, so exported names in the package can use that fact to avoid repetition.
    
    包的导入者将使用名称来引用其内容，因此包中的导出名称可以利用这一事实来避免重复。
    

### **Import for side effect（导入副作用）**

 import a package only for its side effects, without any explicit use. 

导入一个包只是为了它的副作用，没有任何明确的用途。

```bash
# 执行包中init方法
import _ "net/http/pprof"
```

### **The init function**（初始化函数）

1. 用于程序执行前包的初始化
2. Actually each file can have multiple `init` functions.
    
    每个文件可以有多个 `init` 函数（**一个包可以包含多个init函数**）
    
3. 一个包被引用多次，只会初始化一次
4. 同一个包中多个init函数执行顺序没有明确定义（通常按照编译器编译顺序执行），但是不同包的init函数是根据包导入依赖关系决定的，**根据 Go 语言对包初始化的规范，当一个包中遇到多个文件时，会按字母顺序处理**
5. `init`函数在代码中不能被显示调用、不能被引用，否则出现编译错误

### internal package（内部包）

**Go中命名为internal的package，只有该package的父级package才可以访问该package的内容。**

例如：

包路径**`.../a/b/c/internal/d/e/f`
只能被 `.../a/b/c` 的代码层级包引入，不能被`.../a/b/g`或其他的任意目录引用**
